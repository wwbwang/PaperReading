# PaperReading

需要用户登录或网页验证时，可使用[当前机器的持久浏览器](docs/browser-session.md)：运行 `python scripts/browser_session.py start`，从现有网站端口进入返回的私有路径。用户与 agent 操作同一个浏览器，登录状态可保留。

Git 保存应用源码、测试、数据来源记录和校验报告。原始下载、论文 CSV/JSONL、审稿 CSV、构建产物及运行缓存保留在本地，不纳入提交。新检出目录需先按下文同步两个年份的数据，再构建网站；历史快照的来源 URL 和 SHA-256 记录在各年份的 `raw/papercopilot_source.json` 中。

论文库监听 `0.0.0.0:8000`，按会议和年份进入，当前提供 **ICLR 2026、2027**。

## 加载优化

旧版必须先下载约 97 MB 的完整 2027 数据（gzip 后 28.07 MB），包括所有摘要与详细评分，才能显示页面。现在分成三个部分：

- 首页是独立静态 HTML/CSS，合计约 3 KB 压缩内容，不请求论文数据。
- 年份页面先加载所有论文的标题、状态、评分与均分，保留完整分布和列表；2027 数据压缩后约 2.14 MB，2026 约 0.98 MB。
- 关键词标签按当前页批量读取（最多 25 篇），不把全部关键词塞进首屏，也不为展示标签下载摘要。
- 展开论文时才加载对应详情分片，每个年份按 ID 哈希分成 256 片，同一页面共享请求，并仅缓存最近 16 片。全文摘要及详细评分保留完整。

标题与摘要搜索使用本地 SQLite，只返回匹配 ID，不向 OpenReview 发请求，不下载全部摘要；查询参数绑定，保持字面子串匹配。搜索、详情均显示加载或失败状态并支持重试；中止过期搜索，避免快速输入混入旧结果。全文搜索需要本项目的 Python 服务，不能用普通静态服务替代。

HTML/CSS 使用 ETag 重新验证，带内容哈希的评分快照和详情分片使用一年 immutable 缓存；详情版本同时包含论文快照、原始镜像和网页数据格式版本，避免新增作者字段后继续命中旧缓存；所有公开 JSON/HTML/CSS 提供 gzip。SQLite 搜索文件禁止直接通过 HTTP 下载。

## 标题、Keywords 与摘要模糊查询

“对应论文”上方新增 **搜索当前筛选结果**：在当前年份、顶部标题/摘要查询、Keywords、作者、状态和均分共同选中的全部论文中，进一步搜索标题或摘要，覆盖所有分页。结果内搜索仅更新列表、匹配数量及分页，保留当前分布与统计以便比较；修改筛选设置后，搜索词继续作用于新的范围。“清除结果内搜索”仅清空该搜索，“重置筛选”清空所有条件。输入后立即标记为查询中并隐藏旧结果，等待 200 ms 再发起本地索引查询，过期请求会被取消；支持失败重试，不批量下载摘要。搜索失败显示范围不可用，响应结构异常显示错误，不作为零篇结果。

列表标题下和展开详情中展示作者原始关键词，点击任意标签即可筛选。**论文模糊查询** 默认“全部（标题 + Keywords + 摘要）”，也可选择“标题 + Keywords”或任一单字段。支持部分词匹配，例如 `diff` 匹配 `diffusion`；忽略大小写、全角/半角差异，连字符和下划线视作分隔符。多个词按 AND 匹配，词序不限，可出现在所选范围的不同字段中，不提供拼写纠错或语义扩展。左侧“搜索论文”仍按标题/摘要中的连续文字匹配，页面会说明两者差别。

该模糊查询可与标题/摘要搜索、投稿状态、均分选择及结果内搜索组合；切换查询范围自动重新查询并回到第一页，重置筛选恢复“全部”。点击关键词标签会把词填入模糊查询框，沿用当前查询范围。关键词取自两个年份已固定版本的 Paper Copilot 原始镜像，按 forum ID 关联，构建前核验 SHA-256；保留作者拼写，不从摘要推断关键词。目前 62,604 篇主会记录均有关键词。原始论文导出不改写，关键词在网站构建时加入本地索引。

`/api/keywords` 每次最多读取 25 篇；`/api/search` 的 `keyword_scope` 支持 `all`、`both`、`keywords`、`title`、`abstract`。网页显式发送 `all` 作为默认值；接口省略范围时保留旧版 `both` 行为。三个文本字段均预先归一化，不请求外部服务、不增加首屏载荷。当前 2027 快照中 `Video Restoration` 在 `both` 下为 17 篇，在 `all` 下为 42 篇；这些是文字匹配数量，不代表主题相关性判断。

## 主题词云

两个年份均提供词云，基于当前论文结果的全部分页统计作者 Keywords，跟随搜索、作者、状态、均分和结果内搜索更新。每个完整主题在每篇论文中只计一次，字号随包含该主题的论文数增大；颜色仅用于区分，不表示额外权重。鼠标悬停或键盘聚焦可查看篇数与占当前结果的比例。桌面最多展示 60 个高频主题，窄屏最多展示 30 个，实际展示数量及缺失关键词的论文数会明确标注。

点击词语会增加一个独立主题条件，多个主题取交集，并保留原有搜索与评分设置；可点击主题标签移除、清除所有主题或重置全部筛选，最多同时选择 12 个主题。按完整 Keywords 匹配，合并大小写、空格和连字符差异，保留 `C++`、`C#` 等有意义的符号；不自动合并同义词，也不从摘要推断主题。统计为当前快照中的关键词篇频，不代表论文质量或未收录论文的整体趋势。

词云由 `/api/wordcloud` 对当前快照中明确选中的论文 ID 聚合，限制年份、快照和论文范围；服务缓存只读主题索引，不下载新数据。词云独立异步加载，排序和翻页不会重新统计；请求失败可重试，移动端重新排布并防止文字重叠。

## 作者搜索

顶部 **作者搜索** 支持姓名部分匹配，忽略大小写、全角/半角及分隔符；多个词按 AND 匹配、顺序不限，并且必须命中同一位作者，避免把不同合作者的姓与名拼成误匹配。作者条件与标题/摘要、Keywords、投稿状态、均分和结果内搜索取交集，同时更新相应统计、分布和列表；修改作者后回到第一页，“重置筛选”清除作者条件。展开论文可查看原始作者姓名。

作者仅使用会议公开名单；镜像名单按 forum ID 关联并核验 SHA-256，不从预印本或论文题目推断身份。ICLR 2026 有 19,813 / 19,814 篇提供作者。ICLR 2027 的 42,790 篇记录均缺失会议作者，页面明确显示“作者尚未公开（双盲审稿中）”并链接[官方政策](https://blog.iclr.cc/2026/09/02/submission-policies-for-iclr-2027/)；作者身份在审稿结束后公开，更新后的数据包含名单时输入框会自动启用。

`/api/search` 可附加 `authors` 参数，所有词在同一作者的归一化姓名中匹配。当前年份完全缺少作者数据时返回 HTTP 422 和明确提示，不伪装成零条搜索结果。作者索引保存在本地 SQLite 独立表中，姓名只随展开详情加载，不增加首屏论文数据体积。

采集器保留官方公开的 `authors` 字段，以及镜像中的会议作者字段；官方字段或论文本身限制读者时不导出姓名，`Anonymous`、`Anonymous Authors` 等占位值不进入搜索索引。作者列表随 JSONL 和 CSV 导出，未来更新后构建即可启用搜索。网站数据结构变更会更新独立缓存版本，旧页面和新数据不会混用；构建仅重新压缩新增或更新的静态文件。

## 审稿评价正文

评分表在匿名审稿人名字前提供折叠箭头：点击箭头或名字才请求该论文的公开评审，按匿名审稿人代号匹配，在该评分行下方跨列显示概述、优点、不足、问题等原文，再次点击同一名字收起。不设置单独的“具体评价”列或“收起评价”按钮。只提取公开 `Official_Review`，作者回复、公众评论和 meta-review 不会混入；网页按纯文本展示原文，不执行其中的 HTML。正文采集时间单独标注，不覆盖原有评分快照。

获取正文后，若官方比评分快照新增了审稿人，表格会追加对应的评价折叠行，并提示该行不在原评分快照中；评分显示“—”，不将新正文的实时分数混入原快照统计。

**已于 2026-11-15 通过当前持久浏览器取得真实公开评价正文。** 用户登录后，已通过网页核对两个年份的 5 篇论文、16 条评价：ICLR 2027 的 `U1ObEVC4A7`、`001PJNwZiT`、`002z9w7Cev`、`004w3yx1Yp`（各 3 条），以及 ICLR 2026 的 `00HNN8O7Ni`（4 条）。匿名代号与网站评分快照对应，展开正文逐段与官方原始 notes 一致；其中 `004w3yx1Yp` 从网页首次点击触发获取，验证了未缓存论文的完整路径。正文按需获取，不代表已下载所有论文的评审。镜像仍只提供评分等元数据；浏览器验证失效时会明确提示重新验证，不生成评价、不把字数当正文。

抓取器先请求官方公开接口；HTTP 失败时通过当前 node02 的持久浏览器调用同一接口，不导出或复制登录凭据。浏览器需要验证时，由用户在 `/browser/` 私有入口完成，再点击“重新获取”。HTTP 验证失败的十五分钟冷却不阻止浏览器重试；任何路径遇到 429 均暂停一分钟，不切换路径继续请求。

成功正文写入 `iclr<year>/review_text/<forum-id>.json` 并缓存六小时，公开原始 notes 保存在 `raw/review_text/`。公开可见性在浏览器内和写入缓存前分别检查，私有 notes 及限制读者的字段不导出；分页按接口全部 notes 的数量推进，不按筛选后的评审数推进。更新失败仍可阅读上次成功获取的正文，页面标注旧缓存及原采集时间。也可导入从 OpenReview 获取的公开 notes JSON。

批量补齐两个年份的公开正文，使用同一个已登录的持久浏览器：

```sh
python scripts/sync_review_text.py --year 2027 2026 --page-size 250
python scripts/sync_review_text.py --year 2027 2026 --status
```

同步按官方投稿邀请分页，并通过 `details=directReplies` 获取公开 `Official_Review`；每批事务写入 `iclr<year>/review_text.sqlite3`，其中 `reviews` 表保留可展示结果和公开原始 notes。网页直接读取这份缓存，继续支持逐篇获取。数据库和逐篇 JSON 都保留在本地，不纳入 Git；缓存命中不等待其他论文的网络请求，缓存新旧和六小时有效期均按实际采集时间判断，避免共享磁盘时钟偏差的影响。

进度保存在 `.runtime/review-sync/<year>.json`，公开分页记录和最终覆盖核对保存在 `iclr<year>/raw/review_sync/`。重复运行同一命令会从已提交的进度继续；`--max-pages N` 可分批暂停，`--refresh` 开始新一轮同步。遇到限流、验证或登录失效时停止并记录原因，不将失败当成“没有审稿意见”；恢复后重新运行即可续传。完成状态要求投稿 ID 无重复、官方总数稳定，并与本地论文名单完整核对；已抓取但没有公开正文的论文和未覆盖的论文分别计数。此覆盖核对针对正文采集，不会改写原有评分快照。

**ICLR 2027 使用原始 1–4 分尺度，本项目不将其换算成十分制。** 2027 网站按实际出现的 **33 个精确均分**分别画柱，不再按 0.5 分分档。以评分总和/有效评分人数约分作为类别键，所有均分用两位小数标注（如 `2.33`、`2.00`），按数值从小到大等距展示；相同均分跨评分人数合并，显示舍入不会影响计数或筛选。搜索、状态筛选后保留完整均分轴，当前没有论文的均分显示零计数。缺失评分保持 `null`，不作为零分参与平均；无评分论文有独立入口。2026 保留半分区间展示。

目前仍在审稿讨论阶段，`Active` 不是录用决定，评分可能更新。评分表保留 Rating、Confidence、Soundness、Presentation 和 **Informativeness**；2027 快照没有提供 Contribution，不显示虚构的数值。

**覆盖范围：论文元数据和评分仍使用固定版本的第三方公开镜像。** 2026-11-15 已通过 OpenReview 官方主会投稿邀请分页核对 42,790 个公开投稿 ID，集合与本地名单完全一致；结果保存在 `iclr2027/raw/review_sync/coverage.json`。审稿正文另从官方公开记录补齐，不能将这次 ID 核对解释为标题、摘要、作者及实时分数都已逐字段重新采集。`iclr2027/raw/last_error.json` 保留此前 HTTP 403/429 失败的历史记录。

来源固定到 [Paper Copilot 提交 2a56c85](https://github.com/papercopilot/paperlists/commit/2a56c85a36140b68be4510bc504d169d29a16b05)，提交时间 `2026-11-15T00:15:56Z`。已校验此固定提交的 Git LFS SHA-256 与文件大小；镜像实际采集时间未知。评分可能是该镜像采集时的快照值，不是逐轮评分历史。参见 [ICLR 2027 官方审稿指南](https://iclr.cc/Conferences/2027/ReviewerGuidelines)。

`id` 是 OpenReview forum ID；`paper_url` 是讨论页，`pdf_url` 是按 forum ID 构造的官方 PDF 地址，尚未逐篇验证可下载性。`ratings` 与 `reviews` 按位置对应，`rating_mean` 为非空总评分的算术平均。镜像没有提供 review note ID，因此 `review_id`、`review_url` 保持为空；匿名审稿人代号不代表真实身份。`retrieved_at` 是本地获取时间，不是评分修改时间。

**2026 数据独立保存在 `iclr2026/`，并在 `/iclr/2026/` 提供浏览。** 历史快照说明见 [iclr2026/README.md](iclr2026/README.md)。两个年份独立构建评分尺度、来源、详情与搜索库，并校验来源年份和评分范围。

## 抓取、更新与运行

抓取和服务脚本使用 Python 3.10+ 标准库；网站构建使用环境已安装的 Data 仪表盘组件和 Node.js，不需要安装 npm 依赖或提供 API 密钥。以下命令在项目根目录执行。抓取器默认年份为 **2027**；网站构建默认同时生成 **2026 和 2027**。

优先尝试官方公开接口：

```bash
python scripts/sync_iclr.py --year 2027 --source openreview --no-env-proxy
```

官方抓取按 `ICLR.cc/2027/Conference/-/Submission` 分页获取全部状态，提取 `directReplies` 中的 `Official_Review`；不会把作者回复、公众评论或 meta-review 当作审稿评分。缓存位于该年份的 `raw/openreview/`，可重跑续取；`--refresh` 忽略旧缓存。只有唯一论文数与 API 报告总数一致时才标记官方公开范围核对成功。

官方受限时，显式获取镜像并全量核对：

```bash
python scripts/sync_iclr.py --year 2027 --source papercopilot --refresh --no-env-proxy
python scripts/validate_iclr.py iclr2027
python scripts/build_iclr_web.py
```

不加 `--refresh` 时使用已校验的本地镜像。`--no-env-proxy` 表示直接连接；网络需要系统代理时移除此参数。429 和临时服务器错误会有限重试；403 会记录后退出，不覆盖已有导出。

默认构建两个年份和首页；之后只更新其中一年可运行 `python scripts/build_iclr_web.py --year 2027`（或 `2026`），另一年份仍保留。新工作目录先运行完整构建。每年拥有独立稳定的 artifact ID，2027 保留原 ID。构建插件位置变化时可通过 `--plugin-root` 指定安装目录。抓取器的 `--output` 可指定另一数据目录保存额外快照。

构建生成 `web/dist/index.html`、`catalog.json`、`iclr/<year>/` 和 `data/iclr/<year>/<snapshot-hash>/`。前者是会议/年份入口，年份目录是标准 Data 仪表盘，数据目录包含详情分片和只读搜索库。两个构建命令均从校验过的本地论文导出读取数据，在临时项目编译，仅替换目标年份；构建失败保留已上线页面，正常构建不修改 `web/src/data.json`。只有显式 `--prepare-only` 会写入编辑用首屏数据。

前台启动服务，Ctrl+C 停止：

```bash
python scripts/serve_paperreading.py --host 0.0.0.0 --port 8000
```

本次运行中的后台服务 PID 位于 `.runtime/paperreading.pid`，日志位于 `.runtime/paperreading.log`。只停止该服务：

```bash
kill "$(cat .runtime/paperreading.pid)"
```

服务仅提供 `web/dist/` 的公开文件及 `/api/search`、`/api/keywords`、`/api/wordcloud`、`/api/reviews`，不暴露工作目录、原始镜像和 SQLite 文件。搜索严格按会议、年份和数据版本隔离；访问网站不会自动向 OpenReview 请求数据。更新网站数据后重建并刷新即可，修改服务脚本后须重启服务。

展开评价时，已有本地审稿正文（包括已确认无正文的记录）直接读取，不因缓存超过 6 小时而自动联网。未缓存的论文才按需获取；更新已缓存正文使用 `python scripts/sync_review_text.py --year 2026 2027 --refresh`，或 `scripts/review_text.py --year YEAR --paper-id ID --refresh`。页面显示正文的实际采集时间，评分仍属于独立论文快照。

## 多会议、期刊与 Workshop（2025–2027）

`scripts/paper_venues.py` 维护 23 个来源：ICLR、CVPR、ICCV、ECCV、NeurIPS、ICML、AAAI、IJCAI、WACV、BMVC、ACCV、ACM MM、ICIP、ICASSP；TPAMI、IJCV、TIP、TCSVT、TMM、TCI、Pattern Recognition；NTIRE、AIM。首页提供每个来源的三个年份入口，区分已采集记录、单双年不举办和公开数据暂未取得。

```bash
# 首次采集或继续未完成的来源；已有原始响应会经校验后复用。
python scripts/sync_library.py
python scripts/build_library.py

# 更新某个来源：重新请求源索引及公开记录，再增量重建。
python scripts/sync_library.py --venues cvpr tip --years 2026 2027 --refresh-sources
python scripts/build_library.py --venues cvpr tip --years 2026 2027

# 只用本地响应重新解析（例如修复解析器或补充摘要关联）。
python scripts/sync_library.py --venues tip --years 2025 2026 --refresh
```

原始响应、URL、采集时间和 SHA256 位于 `library/<venue>/<year>/raw/`；规范化论文为 `papers.jsonl`，字段覆盖、错误和来源清单位于同目录 `manifest.json`。`library/catalog.json` 保存全部年份的覆盖汇总及清单校验值。大体积原始数据和可重建的逐篇文件留在本地仓库目录，由 `.gitignore` 排除；不会因构建清理。ICLR 2026/2027 继续使用原有 `iclr2026/`、`iclr2027/` 及审稿正文缓存。

来源依次使用公开镜像、官方论文集／录用名单及出版机构登记的 Crossref 元数据，逐来源标注覆盖情况。会议记录按会议届次归档，期刊按 Crossref 的 `published/issued` 年归档，可能与 Early Access 或印刷卷期年份不同。期刊缺失摘要可经已发表 DOI 与 OpenAlex 精确关联；作者保留出版机构正式公开名单，不从预印本推断。镜像中的逐人评分可视化为精确均分，不把录用状态、综合评分或缺失值伪造成审稿人评分。新来源尚未提供的审稿正文明确显示缺失；不声称会议或期刊没有审稿。

已可用的数据刷新失败或意外返回空列表时，保留上一份论文和清单；失败详情保存在该年份的 `refresh-error.json`，下次成功刷新后清除。未逐篇核实 track 的会议论文集不宣称全部属于主会。

构建器在独立临时项目中使用规范 Data 编译器，原子替换单个年份，保留服务端口和其他来源。不可用年份只展示原因及官方链接，不用“0 篇”冒充全量统计。摘要和审稿正文共用本地 KaTeX，支持行内／独立公式，并兼容公开评价中多转义一层的格式命令；无法解析的公式保留原文，禁用不受信任的 TeX HTML／链接功能。

## 首页与作者跟踪

首页以紧凑卡片提供 23 个来源的入口，支持类型、年份及来源名称筛选；手机端自动改为单列。`/authors/` 是作者跟踪入口，初始关注深圳先进院的董超（Chao Dong），支持论文标题、年份、来源、身份核实状态和未读筛选。关注与已读状态保存在当前浏览器的 `paperreading.authors.v1`，不跨设备同步；新收录记录默认未读。

`library/authors/watchlist.json` 保存可跟踪作者的机构、姓名别名和官方身份链接；`chao-dong-siat.json` 保存团队已发表论文目录的解析结果、获取时间及原始响应校验值；`index.json` 保存关联记录和首次收录时间。原始页面留在被 Git 忽略的 `library/authors/raw/`。新增作者时添加独立档案和相应的公开论文证据，不仅按姓名认定身份。

“已核实”要求本地公开作者姓名与团队已发表论文目录的完整标题同时匹配；仅姓名匹配的记录显示为“同名待核实”，默认不展示。团队目录是身份交叉核对证据，年份、作者名单及投稿状态仍使用本地来源记录；不会从预印本推断匿名投稿作者。跟踪只覆盖当前已收录且提供公开作者的记录，同一作品的多个年份或来源保留为独立收录记录。

```bash
# 论文库重建会同步更新作者索引；仅刷新首页及本地作者关联：
python scripts/build_library.py --portal-only

# 重新获取作者团队的公开论文目录，再更新首页和跟踪索引：
python scripts/author_tracking.py --refresh-profiles
```

作者目录抓取失败或解析为空时保留上一份有效证据。该功能按构建更新，不创建定时任务，也不发送外部通知。

### 首页录取与投稿统计口径

`library/conference-statistics.json` 维护已人工核实、附来源与核实日期的会议主会汇总。首页标注“核实”时，录取数与总投稿数都取自同一届主会统计，不与本地论文列表计数混用；标注“本地”时，仅显示本地录取记录数，总投稿数保持未知。列表里有少量公开拒稿不构成全量覆盖证据。

ICML 2025 的官方 Fact Sheet 公布主会录取 3,260 篇、录取率约 27%；RIKEN AIP 公告明确分母为 12,107 篇，计算为 26.93%。本地镜像仅 3,431 条，其中录取状态 3,269 条、拒稿 162 条，因此原先 `3,269 / 3,431` 的展示不能解释为会议录取率。来源链接及范围均保存在该统计文件和首页的数据说明中。论文页继续显示本地实际收录数量，不补造缺失的拒稿记录。
